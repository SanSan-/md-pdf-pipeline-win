# Сборка PDF из Markdown

## Purpose

Автор передаёт статью или каталог материалов и получает один PDF для чтения и печати. Книга объединяет текст, формулы и иллюстрации и сохраняет переходы между разделами. Команды запуска приведены в [руководстве пользователя](../../../README.md), зависимости и порядок их установки — в [руководстве по установке](../../../INSTALL-GUIDE.md).

## Requirements

### Requirement: PDF-001 Выбор материалов и названия книги

Сборщик SHALL принимать файл Markdown в UTF-8 или каталог таких файлов. При выборе одного файла он SHALL сохранять уровни его заголовков и заданные в начальном блоке YAML название, автора и дату. При отсутствии названия используется первый заголовок, затем имя файла без расширения. Для каталога названием служит имя каталога. Параметр `-Title` задаёт название книги при любом входе.

#### Scenario: Выбран один файл среди нескольких статей

- **WHEN** автор передаёт `курс/урок.md` с полями `title` и `author`
- **THEN** PDF содержит статью «урок» с указанными названием и автором, а соседние статьи в книгу не входят

#### Scenario: Передан пустой каталог

- **WHEN** в выбранном каталоге и доступных для обхода подкаталогах нет файлов Markdown
- **THEN** сборка завершается с ошибкой и сообщает, что статьи отсутствуют

### Requirement: PDF-002 Порядок и иерархия разделов

Сборщик SHALL рекурсивно включать файлы с расширениями `.md` и `.markdown` без учёта регистра. В каждом каталоге первым идёт обзор. Он выбирается по имени в порядке приоритета `0-index.md`, `index.md`, `README.md`. Затем располагаются остальные статьи этого каталога, затем подразделы. В каждой из этих двух групп числовые части имён сравниваются как числа. Скрытые элементы, ссылки файловой системы, каталог кеша и служебные окружения пропускаются.

#### Scenario: Во вложенной папке есть обзор и две статьи

- **GIVEN** папка `курс/алгебра/` содержит `index.md` с первым заголовком «Алгебра», статьи `2.md`, `10.md` и непустую подпапку `задачи/`
- **WHEN** автор собирает каталог `курс`
- **THEN** раздел «Алгебра» начинается с текста обзора, за которым следуют статьи 2 и 10, затем раздел «задачи»

#### Scenario: У статьи несколько равноправных разделов

- **WHEN** в дерево входит статья `Разбор.md`, начинающаяся с `# Первый` и содержащая далее `# Второй`, без названия в YAML
- **THEN** в книге оба заголовка находятся на одном уровне внутри раздела «Разбор»

### Requirement: PDF-003 Оглавление, закладки и ссылки

Сборщик SHALL выводить первые три уровня разделов в печатное оглавление и сохранять более глубокую иерархию в закладках PDF. Внутренние ссылки на включённые статьи и их заголовки SHALL вести к соответствующему месту книги с учётом исходного каталога статьи и её собственных якорей.

#### Scenario: Одинаковые заголовки в соседних статьях

- **GIVEN** файлы `первая.md` и `вторая.md` содержат заголовок «Пример»
- **WHEN** в первой статье указаны ссылки `#пример` и `вторая.md#пример`
- **THEN** первая ссылка ведёт к примеру из первой статьи, вторая — к примеру из второй статьи того же PDF

### Requirement: PDF-004 Набор формул и кода

Сборщик SHALL распознавать формулы GitHub Flavored Markdown (GFM) в строке, в отдельном блоке и в ограждённом блоке `math`. LuaLaTeX набирает дроби, индексы и математические знаки. Парные HTML-теги `<sub>` и `<sup>` в строке задают нижний и верхний индексы. Обычные фрагменты и блоки кода сохраняют буквальную запись.

#### Scenario: Формула рядом с примером разметки

- **WHEN** статья содержит формулу `$x^2$`, а рядом показывает ту же запись внутри обратных кавычек
- **THEN** в тексте двойка стоит в верхнем индексе, а в примере кода видны знаки доллара и знак степени

### Requirement: PDF-005 Встраивание изображений и повторная сборка

Сборщик SHALL встраивать изображения из разметки Markdown и тегов HTML `img`. Локальный путь вычисляется относительно файла статьи. Поддерживаются сетевые адреса HTTP(S), встроенные данные `data:image/`, изображения PNG, JPEG, SVG и растровые форматы, читаемые библиотекой Pillow. Из анимации берётся первый кадр. Локальное изображение кэшируется по содержимому, загруженное сетевое изображение повторно используется по адресу.

#### Scenario: В двух главах встречается одинаковое имя файла

- **WHEN** обе статьи ссылаются на `figures/chart.png`, а в их каталогах лежат разные изображения
- **THEN** в каждой главе напечатано её собственное изображение, а после изменения одного из файлов следующая сборка включает его новое содержимое

#### Scenario: Получатель работает без сети

- **GIVEN** зависимости и пакеты TeX установлены, получателю передан кеш ранее загруженного изображения
- **WHEN** он запускает сборку с `-Offline` и указывает этот кеш через `-CacheDir`
- **THEN** изображение встраивается без повторного сетевого запроса

#### Scenario: В автономном режиме нет нужного ресурса

- **WHEN** для сетевого адреса в выбранном кеше отсутствует сохранённое изображение и указан `-Offline`
- **THEN** сборщик сообщает, в какой статье отсутствует изображение, и завершает сборку с ошибкой без обращения по этому адресу

### Requirement: PDF-006 Схемы Mermaid

Сборщик SHALL заменять ограждённый блок `mermaid` изображением схемы и кэшировать результат по тексту блока. Для первого построения требуется Mermaid CLI с доступным браузером.

#### Scenario: Повторное использование готовой схемы

- **WHEN** в кеше уже есть изображение для того же текста блока `mermaid`
- **THEN** сборщик вставляет сохранённую схему без запуска Mermaid CLI

### Requirement: PDF-007 Публикация готового PDF

Сборщик SHALL сохранять готовый PDF по пути `-Output` либо рядом с входным файлом или каталогом под его именем с расширением `.pdf`. Итоговый файл SHALL заменяться после успешной вёрстки и стабилизации ссылок и оглавления. При ошибке сборки прежний PDF сохраняется, команда возвращает ненулевой код завершения.

#### Scenario: В уже собранной книге появилась ошибка

- **GIVEN** по указанному выходному пути уже существует PDF
- **WHEN** для обновлённой статьи невозможно прочитать обязательный рисунок или LuaLaTeX завершился с ошибкой
- **THEN** ранее созданный PDF остаётся доступным по прежнему пути, а команда сообщает причину ошибки

### Requirement: PDF-008 Передача проекта в архиве

Архив SHALL содержать программы сборки и установки, фильтр Pandoc, настройки вёрстки, перечень библиотек Python, пример материалов и руководства по установке и использованию. На стороне получателя сценарии SHALL запускаться из Windows PowerShell 5.1 и находить ресурсы относительно распакованного проекта.

#### Scenario: Сборка после распаковки в другой каталог

- **GIVEN** получатель распаковал архив в каталог с пробелами и установил зависимости по руководству
- **WHEN** он запускает `build.ps1` для каталога `examples/guide`
- **THEN** сборщик создаёт PDF примера с его разделами, формулами и иллюстрацией

#### Scenario: Подготовка пакетов для автономной установки

- **GIVEN** отправитель готовит Windows x64 для сборки статей без доступа к сети
- **WHEN** он следует руководству по установке
- **THEN** он находит официальные ссылки на установщики и пакеты, точные имена пакетов Python и MiKTeX, команду для скачивания пакетов MiKTeX вместе с метаданными и команды установки на принимающем компьютере
- **AND** руководство указывает, как проверить подготовленный комплект по контрольному PDF и по статьям получателя

#### Scenario: Первый запуск из автономного архива Windows x64

- **GIVEN** получатель распаковал автономный архив с установщиками, пакетами Python, базовым комплектом MiKTeX и пакетами для вёрстки
- **WHEN** он запускает `setup-offline.ps1`, а затем `build.ps1 -Source .\examples\guide -Offline`
- **THEN** программы и библиотеки берутся из комплекта или из совместимых локальных установок, а сборка создаёт PDF с формулой и иллюстрацией
