# Markdown в PDF

Конвейер собирает статью или каталог статей в один PDF с оглавлением, закладками и внутренними ссылками. Pandoc разбирает Markdown, LuaLaTeX набирает текст и формулы, Python готовит иллюстрации. Сборку можно запускать из Windows PowerShell 5.1 из любой рабочей папки.

## Первый запуск

Для машины с интернетом распакуйте `md-pdf-pipeline.zip`, откройте папку проекта в PowerShell и выполните команды ниже. Первая команда устанавливает недостающие программы через WinGet и создаёт окружение Python в `.venv`. Для машины без интернета используйте `md-pdf-pipeline-windows-x64-offline.zip`. Он включает установщики CPython 3.13 x64 и Pandoc, два пакета Python, утилиту установки MiKTeX и локальный репозиторий TeX. [Автономная установка](INSTALL-GUIDE.md#на-компьютере-без-интернета)

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -InstallTools
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Source .\examples\guide -Output .\out\guide.pdf -Title "Площадь треугольника"
```

В `out\guide.pdf` появятся оглавление, переход к статье, чертёж, формула и таблица. При первом запуске MiKTeX может запросить разрешение на загрузку пакетов вёрстки.

Для **новых схем Mermaid без интернета** есть отдельный архив `mermaid-tools-windows-x64.zip` с Node.js, Mermaid CLI и браузером. Если все схемы уже есть в переданном кеше, достаточно основного автономного архива. [Запуск Mermaid в Windows](INSTALL-GUIDE.md#схемы-mermaid)

## Собрать свой документ

В первом примере источником служит один файл, во втором — папка со всеми вложенными статьями. Пути с пробелами заключайте в кавычки. Примеры предполагают, что выполнение распакованных сценариев разрешено. При ограничениях используйте форму вызова из раздела «Первый запуск».

```powershell
.\build.ps1 -Source "D:\Материалы\Введение.md" -Output "D:\Книги\Введение.pdf"
.\build.ps1 -Source "D:\Материалы\Курс" -Output "D:\Книги\Курс.pdf" -Title "Курс геометрии"
```

| Параметр | Действие |
|---|---|
| `-Source` | Принимает статью `.md`, `.markdown` или каталог с такими статьями. Кодировка исходников — UTF-8. |
| `-Output` | Задаёт выходной PDF. По умолчанию результат лежит рядом с источником. Например, `D:\Курс\a.md` даёт `D:\Курс\a.pdf`, а каталог `D:\Курс` — `D:\Курс.pdf`. |
| `-Title` | Задаёт название книги. Для каталога по умолчанию используется его имя. Для файла приоритет имеют поле `title` в начальном YAML-блоке, первый заголовок, затем имя файла без расширения. Поля `author` и `date` одного файла попадают на титульную страницу. |
| `-CacheDir` | Выбирает расположение кеша иллюстраций. По умолчанию это `%LOCALAPPDATA%\md-pdf-pipeline\images`. |
| `-Offline` | Берёт сетевые иллюстрации только из кеша. В MiKTeX также отключает автоматическую загрузку пакетов. |
| `-Check` | Отдельная команда `.\build.ps1 -Check` показывает версии Python, библиотек, Pandoc и LuaLaTeX. Полную вёрстку проверяет сборка примера. |

## Как папки становятся разделами

В каждой папке сборщик сначала ищет обзор в порядке `0-index.md`, `index.md`, `README.md`. Первый найденный обзор открывает раздел. Затем идут остальные статьи этой папки, после них — вложенные папки. Имена сортируются с учётом чисел, поэтому `2-пример.md` предшествует `10-задач.md`. Папки без статей, скрытые каталоги, окружения `.venv` и `venv`, `node_modules` и ссылки на каталоги при обходе пропускаются.

Если вложенная папка имеет обзор, заголовок обзора может стать заголовком раздела. Иначе раздел получает имя папки. У статьи с одним вводным заголовком он становится названием статьи, а её подразделы сохраняют относительную глубину. Печатное оглавление включает три уровня. Более глубокие заголовки доступны в закладках PDF. Ссылки вида `[Расчёт](figures/triangle.md#расчёт-площади)` ведут к соответствующему разделу, когда целевая статья входит в сборку.

## Формулы, иллюстрации и схемы

- Для формулы внутри строки используйте `$a^2+b^2=c^2$`. Отдельную формулу поместите между строками `$$`. Поддерживается также блок кода с меткой `math`. Для дробей, матриц, сумм и пределов используется синтаксис LaTeX. В обычных блоках кода разметка остаётся текстом.
- Для рисунка укажите `![Подпись](assets/triangle.svg)`, HTML-тег `<img src="assets/triangle.svg">` или адрес HTTP(S). Относительный путь считается от файла статьи. Две главы могут иметь собственные файлы `img/chart.png`.
- PNG и JPEG сохраняются в исходном формате. SVG преобразуется в PNG, для анимированного изображения берётся первый кадр. Локальные файлы перечитываются, поэтому исправленный чертёж появляется при следующей сборке.
- Блок `mermaid` превращается в рисунок при наличии Mermaid CLI и его браузера. После первой успешной отрисовки схема доступна из кеша. Установка описана в [INSTALL-GUIDE.md](INSTALL-GUIDE.md#схемы-mermaid).

Чтобы передать иллюстрации для работы без сети, выполните первую сборку с явным кешем. На принимающей машине разместите статьи с локальными рисунками в той же структуре, скопируйте каталог кеша целиком и используйте его повторно. Для обновления изображения, которое изменилось по прежнему URL, выберите новый каталог кеша.

```powershell
.\build.ps1 -Source .\articles -CacheDir .\media-cache -Output .\out\book.pdf
.\build.ps1 -Source .\articles -CacheDir .\media-cache -Offline -Output .\out\book.pdf
```

Если обязательное изображение недоступно или LuaLaTeX завершился с ошибкой, команда возвращает ненулевой код. Ранее собранный PDF сохраняется. Путь к рабочим файлам выводится в консоль. При ошибке вёрстки подробности находятся в `book.log` этого каталога.

## Редактор с просмотром Mermaid

Для редактирования статей подойдёт **Obsidian**. Он бесплатно открывает локальные Markdown-файлы и показывает схемы из блоков `mermaid`. Поддержка схем встроена. Для Windows x64 скачайте установщик **Windows → Universal**. [Скачать Obsidian](https://obsidian.md/download) · [Схемы Mermaid в Obsidian](https://obsidian.md/help/advanced-syntax#Diagram)

1. При первом запуске выберите **Open folder as vault → Open** и укажите папку со статьями. Чтобы посмотреть отдельный файл, выберите его родительскую папку и откройте нужную статью на боковой панели. [Открытие папки](https://obsidian.md/help/vault)
2. Нажмите **Ctrl+E**. На месте блока `mermaid` появится схема. Повторное нажатие возвращает к редактированию. Чтобы видеть текст и схему рядом, удерживайте **Ctrl** и щёлкните переключатель режима в правом верхнем углу заметки. [Режимы просмотра](https://obsidian.md/help/edit-and-read)

Obsidian нужен только автору статьи. При сборке PDF новые схемы обрабатывает Mermaid CLI, а готовые сборщик берёт из кеша. [Установка Mermaid CLI и пример схемы](INSTALL-GUIDE.md#схемы-mermaid)

## Передача проекта

`.\pack.ps1` создаёт `dist\md-pdf-pipeline.zip` с программой, ресурсами печати, примером, тестами, инструкциями и OpenSpec. Чтобы собрать также автономный архив, укажите корневую папку подготовленного комплекта, содержащую `offline\installers`, `offline\miktex-basic`, `offline\miktex-packages` и `wheels`. Например, `.\pack.ps1 -OfflineDir .` создаёт `dist\md-pdf-pipeline-windows-x64-offline.zip`. Статьи, их локальные рисунки и кеш для вашей книги передайте отдельно. [Подготовка автономного комплекта](INSTALL-GUIDE.md#подготовка-компьютера-без-доступа-к-сети)

Требования и сценарии приёмки приведены в [спецификации Markdown в PDF](openspec/specs/markdown-pdf/spec.md). Для внесения изменений используйте [карту проекта OpenSpec](openspec/context/00-start-here.md).
